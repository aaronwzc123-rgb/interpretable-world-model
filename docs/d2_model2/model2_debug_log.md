## 实验 1：delta 退火修复

**改了什么**：
- `ndnf_rssm.py:245` clamp 上限 `1.0 → 4.0`（原文件备份于 `model2/backup/ndnf_rssm.py.bak_20260716_233738`）
- `model.rssm.ndnf.delta_delay=500`（原失败版为 1e9，退火从未启动）
- 其余全部沿用失败版基线（`rep_loss=dreamer`、`demo_steps=20000`、单优化器、BCE grounding_loss、n_conj_prior/post=64/48）

**跑了多少步**：完整 300,000 步，正常结束（exit 0），无 NaN。

**score 曲线关键数字**（`episode/score`，按 1 万步分桶均值）：

| 区间 | 均值 |
|---|---|
| 0–20,000 | 0.96（BFS 热启动期） |
| 20,000–120,000 | 全部 ≤0.03（几乎全 0） |
| 120,000–180,000 | **0.019 → 0.053 的微弱爬升**（与 delta 从 2.1 涨到 4.0 并封顶的窗口重合） |
| 190,000–300,000 | **精确回落到 0.000，持续 110k 步**（比原失败版同期的 0.02–0.25 弱震荡还要更彻底地归零） |

`episode/eval_score`：**30 个检查点全部精确等于 0.000**，包括 130k–180k 训练分数出现微弱回升的那段窗口——eval（argmax）和 train（采样）从头到尾都没有一致地学会。

`train/ndnf_delta` 轨迹【事实，退火机制本身工作正常】：0.1（0–15k）→ 指数爬升 → 145,066 步首次触顶 4.0 → 此后到 295,066 步全程稳定停在 4.0，一次没有掉下来过。

Loss 范围：dyn/rep [1.0, 3.58]，ground [0.42, 4.38]，symbolic 有个别尖峰到 33.3，opt/loss 尖峰到 45.2，但全程无 NaN，值域没有失控发散。

**结论**：【事实】delta 退火这次真的按设计工作了（0.1 → 4.0，稳定封顶），排除了"退火从未启动"这个已实锤的病灶。但按实验1预先约定的判据（150k–300k 窗口 score 需爬过 0.5 且趋势向上才算 delta 是主因），**未达标**——该窗口内 score 均值峰值仅 0.053，且后半段（190k 起）反而彻底归零，eval_score 全程 0。【推断，因为有直接对照数据支持而非纯猜测】delta 退火**不是（至少不是唯一）主因**，说明失败版病灶不止 delta 这一个,或者 delta 修好后暴露出了另一个更根本的瓶颈。

**下一步**：进入实验 2（去掉 BFS 热启动，`demo_steps=0`），在实验1配置基础上只改这一个变量。

## 实验 2：去掉 BFS 热启动

**改了什么**：在实验1配置基础上，`+trainer.demo_steps=20000 → 0`。其余（`delta_delay=500`+clamp 4.0、`rep_loss=dreamer`、单优化器、BCE、n_conj 64/48）不变。logdir: `logdir/m2fix_exp2_nodemo_s0`。

**跑了多少步**：完整 300,000 步，正常结束（exit 0），无 NaN。`ndnf_delta` 轨迹与实验1几乎完全一致（145k 步触顶 4.0 并保持），确认这条不受 demo_steps 影响，退火机制本身稳定可复现。

**score 曲线关键数字**（`episode/score`，1 万步分桶均值，无热启动所以从 0 开始就是策略自己在探索）：

- 全程在 **0.000–0.184 之间随机波动**，没有 20k-30k 那种断崖式回落（因为没有热启动可回落），但也**没有出现持续爬升的趋势**：0-100k 窗口峰值 0.179（80k-90k 桶），100k-120k 短暂到 0.183-0.184，之后 130k-300k 大多数桶又回落到 0.00-0.05 区间。
- `episode/eval_score`：**30 个检查点依然全部精确等于 0.000**，和实验1、和原失败版完全一致。

**结论**：【事实】去掉热启动后，训练不再出现"热启动结束后断崖式归零"的现象（符合预期，因为没有热启动可断崖），但也**没有出现判据要求的自主学习信号**（0-100k 内应缓慢爬升到至少 0.2-0.3 并保持，实际只在个别桶摸到 0.18 后又回落）。eval_score 与实验1、原失败版三者完全一致地卡在 0.000，说明"策略学会等喂答案"**不是（至少不是唯一）主因**——有没有热启动，train score 的量级和 eval_score=0 这两个核心症状都没有改变。

**下一步**：进入实验 3（优化器分层：world model / actor / critic 拆成三个优化器，学习率对齐成功版）。

## 实验 3：优化器分层

**改了什么**：`dreamer.py`（备份于 `model2/backup/dreamer.py.bak_20260717`）把单一 `LaProp` 优化器拆成三个独立实例——`_model_optimizer`（rssm/encoder/reward/cont/decoder 等世界模型模块）、`_actor_optimizer`（仅 actor）、`_value_optimizer`（仅 value），三者仍是 LaProp（不换算法）、`betas/eps` 不变，只是分别配了各自的学习率：`model_lr=1e-4`/`actor_lr=3e-5`/`value_lr=3e-5`（`configs/model/_base_.yaml`，直接照抄成功版数值），AGC 裁剪仍对全体参数一次调用（读 `optim/agc.py` 确认是逐参数张量算裁剪比例，不是全局 norm，拆不拆等价）。5000 步冒烟测试确认三个学习率在 resolved config 里确实分开生效（1e-4/3e-5/3e-5）且无崩溃后，跑了完整 300k 步。基于实验2的配置（`demo_steps=0`）。

**跑了多少步**：完整 300,000 步，正常结束（exit 0），无 NaN。`ndnf_delta` 轨迹与实验1/2 完全一致（145k 触顶 4.0），确认分层没有影响退火机制。

**score 曲线关键数字**：

- `episode/score` 全程在 **0.02–0.18 之间波动**，比实验2（同样无热启动，单优化器）噪音略小、**后半段（200k-300k）没有衰减到 0**：exp2 同区间 10 个桶均值约 0.025（含两个精确 0.000 的桶），exp3 同区间 10 个桶均值约 0.075，最后一个记录桶（280k-290k）还有 0.145。**这是三个实验里目前 train score 表现最好的一次**，但依然是无明显趋势的噪音震荡，不是稳定爬升。
- `episode/eval_score`：**30 个检查点又是精确全部等于 0.000**——和实验1、实验2、原失败版完全一致，无一例外。

**结论**：【事实】优化器分层对 train score 的噪音下限有轻微改善（后半程不再频繁跌到精确 0），但**没有解决核心症状**。更值得注意的是一个跨实验的模式：【事实】三个独立 300k 步实验（delta 修复、去热启动、优化器分层）、总共 90 个 eval 检查点，`episode/eval_score` **无一例外精确等于 0.000**，而同一批 run 里 `episode/score`（train，靠 rsample 随机探索）却能不时摸到 0.5-0.8 的单集分数。train 有非零信号、eval 从未有过一次非零，这个反差在改了三个不同变量之后依然分毫不差地复现，**不太像"策略还没学好"（那样至少偶尔应该在 eval argmax 上蒙对一次），更像 train（rsample 随机采样）和 eval（mode/argmax 确定性策略）之间存在系统性断裂**。【推断】不特别针对某个已测变量，怀疑指向 eval 路径本身——例如 argmax 是否稳定卡在某个不产生进展的动作（此前诊断中就实锤过一次类似的 "argmax 卡在 done 动作" 问题，当时通过把动作空间从 7 砍到 5 解决，但没人验证过砍完之后 argmax 卡没卡在新的哪个动作上）。

**下一步（建议，未执行）**：在烧掉实验4/5的 GPU 时间之前，先花几分钟低成本验证这个假设——加载 `m2fix_exp3_optsplit_s0/latest.pt`，跑几条真实 eval episode，打印每步 argmax 动作分布，看是否卡在固定动作/固定谓词状态。如果实锤是 argmax 死锁，那接下来两个既定实验（损失函数简化、合取子容量）大概率也救不了 eval_score，应该先修 eval 路径这个新发现的病灶，而不是照原顺序继续跑候选4/5。
